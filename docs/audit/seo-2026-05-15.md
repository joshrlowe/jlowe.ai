## 2. Metadata findings

### Description-inconsistency bugs (confirmed)

- **`/contact`** (`pages/contact.tsx:229` vs `:245`). Loading branch says `"Get in touch with Josh Lowe for AI consulting and engineering projects."`. Main render says `"Get in touch with Josh Lowe for AI consulting, machine learning projects, and full-stack development."`. Crawlers can race the loading branch on cold ISR. **Fix:** hoist a single `META_DESCRIPTION` constant; render the same `<SEO>` regardless of `contactData` state.
- **`/about`** (`pages/about.tsx:105` vs `:134`). Empty-state branch uses `"Learn more about my experience and skills"` (37 chars — too short, below the 150-char threshold). Main branch derives from `professionalSummary` truncated to 160. **Fix:** identical pattern — single hoisted fallback.

### Length issues

- **Default description** in `components/SEO.tsx:15`: `"Full Stack Developer specializing in modern web technologies."` is 62 chars — under target (150-160). Stale identity, too: site copy says "AI/ML Engineer" and "AI consultancy".
- **Title doubling:** `components/SEO.tsx:20` appends ` | Josh Lowe` only if `title` does not already include the string. `/projects`, `/contact`, `/articles` already pass `"… - Josh Lowe"` so they skip the suffix, but the OG default's `og:site_name="Josh Lowe"` already conveys this — consider standardising on a single separator (` — ` is industry preference; current code mixes ` - ` and ` | `).
- **`pages/index.tsx:74`** title `"Josh Lowe - AI/ML Engineer | Portfolio"` = 39 chars — fine but the `| Portfolio` suffix is redundant. Recommend `"Josh Lowe — AI/ML Engineer & Consultant"` (44).
- **Admin pages** (`_app.tsx:133`) only set `<title>` — no `<meta name="robots" content="noindex,nofollow">`. They redirect on missing JWT but until then crawlers can pick up the login page. **Fix:** add `noindex,nofollow` next to title in the admin branch, same as design.

### Open Graph / image gaps

- **No OG image dedicated for social.** `components/SEO.tsx:16` defaults to `/images/logo.png` (1536×1024, not the 1200×630 social standard, transparency unknown). Twitter `summary_large_image` cards crop hard.
- **No `og:image:width` / `og:image:height` / `og:image:alt`** in `SEO.tsx:32`. Add them once you produce a 1200×630 image.
- **No `og:locale="en_US"`**, no `twitter:site` / `twitter:creator` handle.
- **Project detail OG image** (`pages/projects/[slug].tsx:75-81`) only picks `images[0]` if it's a raw string and silently undefineds in every other case — most rows likely fall through to the page default. Add a normalizer in `lib/utils/projectTransformer`.

### Other on-page

- `pages/_document.tsx:8` has empty `<Head />` — no `<link rel="icon">`, no `<link rel="apple-touch-icon">`, no `<link rel="alternate" type="application/rss+xml">` (consider for `/articles`).
- `lang="en"` is set on `<Html>` — good.
- Canonical is set in `SEO.tsx:44` but **defaults to `https://jlowe.ai`** when caller omits `url`; `/articles`, `/projects` and dynamic pages must always pass `url`. Today `pages/projects.tsx`, `pages/index.tsx`, the OG bits on `/projects/[slug]`, and the loading branches of `/contact` and `/about` all rely on the default — producing duplicate canonicals across many routes. **Fix:** make `url` a required prop and pass it everywhere.
- No `<meta name="author">`, no `<meta property="article:published_time">`, no `<meta property="article:author">` on `BlogPosting` pages.

## 3. JSON-LD recommendations

`next/script` with `type="application/ld+json"` + `strategy="afterInteractive"` is fine; a tiny `<JsonLd data={...} />` wrapper component is cleaner. None of these need server rendering — Google still parses scripts on first render. Use schema.org JSON-LD; no Microdata.

### Sitewide (mount in `_app.tsx` default-layout branch only)

`WebSite` + `Person` (combine as `@graph`):

```json
{
  "@context": "https://schema.org",
  "@graph": [
    {
      "@type": "WebSite",
      "@id": "https://jlowe.ai/#website",
      "url": "https://jlowe.ai",
      "name": "jlowe.ai",
      "publisher": { "@id": "https://jlowe.ai/#person" },
      "inLanguage": "en-US"
    },
    {
      "@type": "Person",
      "@id": "https://jlowe.ai/#person",
      "name": "Josh Lowe",
      "url": "https://jlowe.ai",
      "image": "https://jlowe.ai/images/og-default.png",
      "sameAs": [
        "https://linkedin.com/in/<handle>",
        "https://github.com/joshrlowe",
        "https://x.com/<handle>"
      ]
    }
  ]
}
```

(`sameAs` URLs are stored on the `Contact` model — read from `contactData.socialMediaLinks` in `getStaticProps` of `_app.tsx`'s ancestor, or pass via `pageProps`.)

### `/projects/[slug]` — `CreativeWork` (default) or `SoftwareSourceCode`

Use `SoftwareSourceCode` when the project has a `githubUrl` and a `programmingLanguage`; otherwise `CreativeWork`. Both share:

```json
{
  "@type": "SoftwareSourceCode",
  "name": "<project.title>",
  "description": "<shortDescription>",
  "author": { "@id": "https://jlowe.ai/#person" },
  "dateCreated": "<project.startDate>",
  "datePublished": "<project.releaseDate>",
  "url": "https://jlowe.ai/projects/<slug>",
  "image": "<first image>",
  "codeRepository": "<project.githubUrl>",
  "programmingLanguage": "<derived from techStack>",
  "keywords": "<tags join>"
}
```

Add `BreadcrumbList` for `Home › Projects › <Title>`.

### `/articles/[topic]/[slug]` — `BlogPosting`

```json
{
  "@type": "BlogPosting",
  "headline": "<post.title>",       // truncate to ≤110 chars
  "description": "<metaDescription || description>",
  "image": ["<ogImage || coverImage>"],
```

Plus `BreadcrumbList`: `Home › Articles › <topic> › <title>`.

### `/articles` (index) — `Blog` + `ItemList`

Helpful but lower priority. Type `Blog` with `blogPost` items each as truncated `BlogPosting`.

### `/projects` (index) — `CollectionPage` + `ItemList`

Same shape; lower priority.

## 6. Favicon set audit

**Present in `public/`:**

- `favicon.ico` (32×32, single icon) — `public/favicon.ico`
- `images/logo.png` (1536×1024, opaque PNG) — re-used as PWA icon + OG default

**Missing per Google + Apple + PWA recommended set:**

| File                                     | Purpose                              | Source needed |
| ---------------------------------------- | ------------------------------------ | ------------- |
| `favicon-16x16.png`                      | legacy browser tab                   | square        |
| `favicon-32x32.png`                      | desktop browser tab                  | square        |
| `favicon.ico` (multi-res 16/32/48)       | replace current single-size .ico     | square        |
| `apple-touch-icon.png` (180×180, no alpha) | iOS home screen                    | square, opaque |
| `icon-192.png` (192×192, maskable)       | Android PWA install                  | square, maskable safe zone |
| `icon-512.png` (512×512, maskable)       | Android PWA splash + install         | square, maskable safe zone |
| `safari-pinned-tab.svg` (monochrome)     | macOS Safari pinned tab              | monochrome SVG |
| `og-default.png` (1200×630)              | Open Graph + Twitter default         | landscape, ≤300KB |
| `og-default-square.png` (1200×1200) (optional) | LinkedIn / Discord fallbacks   | square        |

Notes:

- The current `manifest.json:10-22` references `/images/logo.png` for both 192 and 512 — **wrong dimensions** (logo is 1536×1024, not square). PWA install will reject or render letterboxed. Need real 192/512 squares.
- `purpose: "any maskable"` requires a maskable-safe zone (10% inner padding). The current logo doesn't honor this.
- Once artwork is supplied, link the standard set in `pages/_document.tsx:8` `<Head />`:

```tsx
<link rel="icon" href="/favicon.ico" sizes="any" />
<link rel="icon" href="/favicon-32x32.png" sizes="32x32" type="image/png" />
<link rel="icon" href="/favicon-16x16.png" sizes="16x16" type="image/png" />
<link rel="apple-touch-icon" href="/apple-touch-icon.png" sizes="180x180" />
<link rel="mask-icon" href="/safari-pinned-tab.svg" color="#bb1313" />
```

User has not yet supplied source artwork — block on that, generate the full set with [realfavicongenerator.net](https://realfavicongenerator.net) once a 1024×1024 master exists.

## 7. E-E-A-T author metadata

Concrete moves to surface authority credibly across the site:

1. **Site-wide `Person` JSON-LD** (sec. 3) — single source of truth: name, jobTitle (Tech Lead), worksFor (BidOps), alumniOf (UCF), `sameAs` social links.
2. **`/about` page** — wrap the Hero section in a microdata-friendly block; the JSON-LD above already covers the structured side. Add a visible "About this site" block at the footer of `/about` (`pages/about.tsx` after line 226): one paragraph naming Josh, UCF MS CS, BidOps role, link to LinkedIn/GitHub. Helps E-E-A-T human signals + AI crawlers.
3. **Article author chip** (`pages/articles/[topic]/[slug].tsx:146`) currently renders `By {post.author}` — promote this to a link to `/about`, render an avatar (use `welcomeData` profile photo), and inject `BlogPosting.author` JSON-LD with `@id` matching the sitewide Person node. Reuse `<AuthorByline />`.
4. **Bio footer on every article** — short component below the comments showing photo + credential ("Josh Lowe — MS CS @ UCF · Tech Lead @ BidOps · building AI systems for production"). Reinforces author authority on every leaf page.
5. **`<meta name="author" content="Josh Lowe">`** in default SEO and `<meta property="article:author" content="https://jlowe.ai/about">` on BlogPosting pages.
6. **Add `LinkedIn`, `GitHub`, optional `ORCID`** to `Contact.socialMediaLinks` and surface in JSON-LD `sameAs` — strongest external corroboration signal.
7. **Date credibility:** ensure `dateModified` is always `post.updatedAt` (not `datePublished`) — `pages/articles/[topic]/[slug].tsx` reads both already; expose both in BlogPosting.
8. **Topic clustering:** the `/articles/[topic]/[slug]` URL implies a topical hub. Build a `/articles/[topic]` index (currently missing — only `[slug]` exists under `[topic]`) to act as a pillar page. Massive E-E-A-T + topical authority lift for cheap.
