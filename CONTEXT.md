# jlowe.ai — Domain Context

This file captures the project's domain language, naming conventions, and the patterns Claude should reach for when extending the codebase. It complements `CLAUDE.md` (technical architecture) by documenting *why things are named what they are* so refactors and new features stay coherent.

> Started 2026-05-15 during the `cleanup/2026-05-15` branch work. Sections are appended by analysis agents (`improve-codebase-architecture`, `grill-with-docs`) and by hand as decisions crystallize.

## What jlowe.ai is

The personal site / consultancy front for Josh Lowe. It serves three audiences:

1. **Prospective clients** — landing on `/`, `/projects`, and the chat funnel for inbound leads (chat → meeting booking via Cal.com).
2. **Readers** — long-form `/articles/[topic]/[slug]` SEO content, comments (Comment-moderated by Claude Haiku), playlists.
3. **Josh as the operator** — admin UI under `/admin/*` for editing every content surface (Welcome, About, Projects, Posts, SiteSettings, comments queue, etc.).

The site doubles as a showcase of personal engineering taste, so visual polish (Three.js / GSAP background, the Liquid-Heat / Supernova palette, animated headings) is load-bearing — not decoration.

## Domain vocabulary

- **Welcome** — hero copy on `/` (model: `Welcome`).
- **About** — long-form bio, leadership, education, skills, certifications, hobbies (model: `About`; admin surface: `AboutSettingsSection.tsx`).
- **Project** — case studies / portfolio entries with `ProjectTeamMember` joins (model: `Project`).
- **Post / Article** — long-form writing under `/articles/[topic]/[slug]` (model: `Post`). The URL says "articles" but the model is `Post`; this is intentional — "post" is the creator-side noun, "article" is the reader-side noun.
- **Playlist** — curated post collections (`Playlist` + `PlaylistPost` join).
- **ChatSession / ChatMessageRow** — the lead-funnel chat thread keyed by HttpOnly `chat_session_id` cookie. Each session has an inferred `intent` (`evaluating`, `learning`, etc.) classified per message by Claude Haiku.
- **KnowledgeChunk** — RAG corpus row with `embedding vector(1024)` + `tsv tsvector`. Generated by Inngest fan-out from `knowledge/reindex.requested`. **Raw SQL only** (Prisma can't bind pgvector / tsvector first-class).
- **Comment / CommentVote** — public-facing comment thread with `moderationStatus` enum (`approved | held | rejected`) replacing the legacy `approved` boolean (mirrored on every write). `held` items surface in `/admin/comments`.
- **SettingsSection** — the admin-side concept for "the editor for one content surface" (e.g. `AboutSettingsSection`, `ContactSettingsSection`, `GlobalSettingsSection`, `HomeSettingsSection`, `ProjectsSettingsSection`). They share patterns (load → edit → save) but are not yet generalized.

## Architectural conventions worth preserving

- **Pages Router** — not App Router. Server-only logic lives in `pages/api/*`, `getServerSideProps`, `middleware.ts`. **Auth lives in middleware**, not `getServerSideProps` (`lib/auth.ts:requireAuth` always returns `props: {}`).
- **API handlers** are wrapped via `createApiHandler({ GET, POST, ... })` with `handleApiError`; admin routes additionally wrap with `withAuth`. Rate limiting is `checkRateLimit` (Upstash, fails open in absence).
- **Bedrock-only LLMs.** Three Claude variants: chat (Sonnet 3.5 v2), moderation (Haiku 4.5), intent classification (Haiku 3). Region `us-east-1`. Credentials validated lazily.
- **Inngest for async**, with one `serve(...)` handler at `/api/inngest`. Events typed in `lib/jobs/events.ts`. Local dev requires both `npm run dev` and `npm run jobs:dev`.
- **Vercel Cron**, not Inngest, for nightly digests (`pages/api/cron/qualified-leads-digest.ts`).
- **Observability via Langfuse**, lazy singleton with frozen no-ops when keys are absent. One trace per chat request, threaded through retrieval / classification / streaming.
- **Tailwind v4 with `@theme` block.** No shadcn/ui. Token system: Supernova + Liquid Heat dual palette in `styles/globals.css`. Section-scoped overrides start ~line 741.

## Patterns to standardize (open questions)

- The `admin/*SettingsSection.tsx` files duplicate the load → form-state → save pattern. A `useSettingsForm<T>` hook + `<ArraySection>` primitive could collapse a lot. Tracked in `docs/refactor/AboutSettingsSection-plan.md`.
- The dynamic-import pattern in `GitHubContributionGraph` (lazy load + 15s timeout + error fallback) might generalize to a `useDynamicComponent` hook reused by `SpaceBackground` + `FluidHeatShader`. Tracked in `docs/refactor/GitHubContributionGraph-plan.md`.
- Per-page JSON-LD is missing — being added in Wave 6 via `<JsonLd data={...} />`. Schema.org types: `WebSite` + `Person` sitewide; `Person` extended on `/about`; `CreativeWork` on `/projects/[slug]`; `BlogPosting` on `/articles/[topic]/[slug]`.
